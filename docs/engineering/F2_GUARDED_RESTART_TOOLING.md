Its read-only boundary proof checks operation/intent/artifact authority tuple, UUID/inode/hash/size, fresh copy inodes, exact retained anchors, copy counts and photo/outbox effects. The controller requires the existing staging authorization, exact injected/named service match and known-production refusal, mandatory confinement/fencing, explicit existing absolute SQLite DB or valid PostgreSQL configuration, absolute photo root, and explicit synthetic-case confirmation. ## Lost-ack correlation and repeated W4 setup

The old driver used `proxy.captured[0]`. A synthetic executable regression using the exact pinned parent reproduces [401,201] selecting401 before the change and the intended201 after it. This does not reclassify the original failed target result.

The new proxy records an arrival attempt ID and non-secret method/path/identity metadata. W2 matches exact POST path and generated Idempotency-Key. W4 matches the exact POST finalize route with its existing intake ID; no production key is invented. Query-bearing/wrong method/path/key requests cannot match. Exactly **one matching attempt and one complete matching response** are required; duplicates, incomplete/aborted/oversized/error responses or ambiguous evidence fail closed. Selection never searches for a successful status. Status201 is checked only after identity correlation. Requests before or after the intended request cannot supply acceptance.

The proxy consumes the entire upstream response and verifies HTTP completion before destroying the downstream socket. Captures contain no raw bodies/headers/cookies; only bounded identifier/status/completion metadata. Authentication is forwarded only to the selected upstream. Attempts are bounded to16 and responses are bounded to1MiB and upstream total duration to30 seconds; exceeding either is not acceptance. Generic transport errors are not printed as raw credential-bearing strings.

`w4` and `w4-setup` edit **only the newly created intake's title** to a UUID-unique `F2 synthetic ...` value through the ordinary proposal-field review API, then perform normal stock acceptance. They never submit SKU, rename/delete an existing product or rewrite DB rows. `w4-setup` stops Applied with one staged photo; it never finalizes. `w4-replay` requires the original W4 IDs, compares the complete product list immediately before/after, retains those IDs and verifies no new photos.
