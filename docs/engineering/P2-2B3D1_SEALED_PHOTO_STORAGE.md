## Storage contract

The authority stores stable operation/owner/claim nonce, monotonic generation and live lease; immutable main/thumb keys and source SHA-256; persistent sealed artifact records (operation/generation, relative path, byte lengths, SHA-256 and exact device/inode strings); and immutable physical root identities. An artifact ID cannot retarget another operation/generation. Input Buffers are limited to10MiB and snapshotted; tokens are copied/frozen before awaits. This fixture Buffer API is not a new full-API multipart ingress or memory acceptance result.

All cooperating **claim/reclaim and publication/compensation** calls must acquire the same exclusive wx/0600 per-operation marker under a private0700 root. Marker contents contain an operation ID and random invocation nonce, not a PID or age grant. A normal invocation releases only the exact device/inode and invocation nonce it created, after its DB/native callback has settled. A replacement/missing marker causes failure; it is not removed. Write/fsync failure leaves the marker retained. SIGKILL leaves it in place. A crash-retained marker blocks every later claim/publication for explicit operator review; there is no stale-file timeout, deletion, quarantine or auto recovery. This deliberately trades availability/disk retention for safety. A validated mutation section is non-preemptible by lease expiry: reclaim stays blocked until native/synchronous publication and its acknowledgement handling settle, or until the process dies and leaves a review-required marker. TTL does not revoke an open descriptor or authorize stealing an active marker.

Physical root identities are registered once by the durable authority before granting work. Replacing/renaming a private root cannot reset the namespace in a new instance; device/inode mismatch fails closed. Root aliases, symlinks, permission/configuration changes or filesystem restoration require separate review, never automatic root rebinding. Marker safety assumes trusted/cooperating code owns these private roots; this is not a sandbox against a malicious same-UID host process, root user or manual removal of markers.

Long-running native encodes happen outside the mutation marker only in immutable operation/generation/unique-attempt private directories. New generation work has different names. If old native work finishes after reclaim, it can alter only old private outputs; revalidation prevents sealing/publication for that stale token. Producer promises are awaited before sealing.

Sealing copies each completed raw output to a separately created COPYFILE_EXCL inode, then closes/chmods it read-only and computes bounded64KiB-chunk hashes. Canonical links never share an inode with an encoder's raw output. A retained native raw descriptor cannot mutate sealed/canonical bytes. Zero, missing, oversized, changed, symlinked or byte-identical-but-replaced sealed inodes are refused. Exact inode identity uses BigInt filesystem reads serialized as strings; no lossy numeric inode authority. Unexpected hardlink aliases are refused. All intermediate/failed seals are retained.

Publication holds the marker across authoritative generation/lease validation, artifact/binding reads, sync filesystem work and DB acknowledgement. It uses linkSync with atomic no-overwrite semantics on the same filesystem. EXDEV and other filesystem errors fail closed; there is no copying/renaming over a canonical destination. Identical existing bytes are an idempotent no-write result, not a transfer of ownership/deletion rights. Conflicting or zero-byte existing output is retained and rejected. A partial two-link publication is retained, not compensated by deletion. Canonical IDs, key spelling and URL shape derive from immutable server bindings, not private generation paths.

Canonical compensation is intentionally retain-only. It still validates token/marker/authority and rejects stale generations; it never follows URL strings to delete a file. Historical/outbox-only/ambiguous bytes remain protected without guessing whether COMMIT succeeded. Private garbage collection and canonical deletion permissions are not implemented.

## Why this closes the three protected counterexamples

1. Newer-generation bytes survive stale compensation: a stale token is rejected before the mutation boundary, and even current canonical compensation only returns retained. The old URL-based delete API is never given canonical capability paths.
2. Escaped SQLite callbacks cannot use this boundary: the actual intake transaction callback runs inside an inherited forbidden AsyncLocalStorage scope. Rejecting its Promise still does not cancel arbitrary JavaScript; instead, later protected filesystem calls fail before I/O. Internal authority callbacks also revoke their mutation lifetime if an asynchronous result escapes a synchronous SQLite transaction. Existing unwrapped/raw APIs remain outside the guarantee.
3. An older deterministic preparation writes only its private raw namespace. Reclaim prevents old sealing/publication; immutable source identity refuses a different-image retry. The new publication primitive never replaces an existing main/thumbnail, so a later thumbnail conflict cannot follow an overwritten newer main. Before/after hashes and inode checks are recorded. The original negative two-process baseline remains in inherited evidence.

The contract does not rely solely on a DB row lock. PostgreSQL can lose its connection after validation while the process still reaches linkSync. The passing Linux regression terminates only the selected disposable worker connection, identified by backend PID + unique application name + current test database. Reclaim must remain blocked by the filesystem marker while the old worker can still perform I/O. Once its callback/connection failure settles, the live invocation releases its marker; only then can a new generation claim and make an idempotent same-input publication. A killed process cannot release its marker and therefore remains review-required. This is tested separately from normal row-lock parity.

## Atomicity, compatibility and remaining rollout gates

SQLite authority callbacks perform only synchronous DB operations and bounded synchronous publication/sealing actions. Unexpected Promises revoke the filesystem lifetime before rollback. PostgreSQL uses the inherited real transaction/row-lock contract under the same filesystem marker. Test adapters create intent, generation and binding atomically; persist seals under the same token transaction; retain generation/outbox history; and compare roots without updating an established identity. These tables are probe_photo_* only, applied to guarded disposable schemas/WAL files. A real provider must use exclusive transaction connections, authoritative DB clocks and the same physical namespace across all workers. The prototype's injected logical milliseconds are not a production TTL policy.

New prepared/sealed outputs and canonical file publication cannot form one atomic transaction with photo/outbox metadata. Crash/ambiguous acknowledgement leaves retained intent-owned bytes. Full photo/AI/outbox committed-state adoption, retries and historical/publishing reference census remain future integration work; the new capability does not synthesize metadata or outbox events to hide ambiguity. The unchanged37 crash workflow suite and51 PG integration suite validate existing behavior separately from this foundation.

All legacy and mixed-version writers, outbox handlers, cleanup jobs and other paths must be excluded or adopted before a production rollout. An actor calling the old repository directly can bypass the marker; that is unsupported and must not coexist with enabled capability writers. Canonical root placement, namespace identity and operator marker handling require an explicit rollout/maintenance protocol. #396 stays OPEN. #390's original24-MP/512-MiB/384-MiB resource gate stays BLOCKED; green CI and tiny images do not establish memory readiness.

## Disk, cancellation and failure policy

Raw output and sealed copies occupy independent payload bytes; canonical hardlinks add no third copy on one filesystem. The conservative per-attempt bound is up to10MiB input + two16MiB raw outputs + two16MiB sealed copies (74MiB), excluding DB/WAL, failed attempts and metadata. The existing42MiB ingress reservation does not cover this bound, so this capability must not be connected to HTTP ingress without separate budget validation. No quota change, scavenger or space-recovery deletion is implemented.

Cancellation cannot release shared mutation ownership while native work is still in flight. Current producer adapters await actual native completion; they have no public early-release/repair API. Abort/error/crash/ENOSPC, zero outputs, DB outage, marker release failure and unknown identities preserve bytes and fail closed. Full HTTP abort/shutdown integration is unsupported pending route adoption; inherited admission regressions remain unchanged. No production readiness claim is made.
